# P005 — Select upstream emulation foundation

**Status:** complete as an emulation-foundation decision and executable-selection phase. **Review date:** 2026-10-23. **Branch:** `main`.

**Selected target:** Apple M1 / T8103 / H13G; Mac mini (M1, 2020), board J274.

**Runtime boundary:** the executed payload is generic ARM64 on QEMU `virt` with TCG, Cortex-A57 and PL011. No Apple CPU/device implementation or T8103 Linux boot is established; G4 remains unrun.

## Requirement and delivered evidence

The canonical P005 requirement is unchanged: document why AArch64 QEMU TCG is the initial executor rather than a second ISA interpreter. Its exit condition is an architecture decision recording limits and alternatives.

| Acceptance item | Delivered evidence |
|---|---|
| Explicit foundation decision | [ADR 0001](../decisions/0001-qemu-tcg.md) accepts full-system AArch64 TCG on Linux/WSL2 x86_64, identifies `aarch64-softmmu` and separates future Apple CPU/board work. |
| Reason for reusing the executor | The ADR explains translation, architectural state, exceptions, software MMU and device infrastructure, and the duplicated engineering obligations of a new interpreter. |
| Alternatives and limits | Seven alternatives are assessed, with bounded reference uses and reconsideration criteria. PAuth algorithm selection, exclusive-access/ordering, timing, platform identity, performance and build-provenance limits are explicit. |
| Primary-source provenance | [P005 references](../REFERENCES.md#p005-emulation-foundation-evidence) record 13 pinned QEMU sources and two live primary project sources. Source snapshots do not become verified build dependencies. |
| Executable enforcement | [The existing smoke runner](../../tools/run_arm64_smoke.py) selects `-accel tcg` with no fallback, rejects emulator errors even after a marker, and validates a finite timeout in `(0, 300]` seconds before launch. |
| Regression and integration | [16 focused tests](../../tests/test_arm64_smoke.py), nine target declarations checked by the existing validator, linked architecture/development guidance, and compiler/emulator/hash output in the existing CI smoke job. |

The implementation started from `dd250aa3c39b117fd0f974a3489d9eb5d3a0650e`, preserving all P001–P004 contracts, every original phase requirement and the hardware registry.

## Three verification passes

1. **Requirement and source review.** Mapped the exact acceptance condition to the decision, alternatives and limits. A separate source reviewer checked the pinned upstream contents and source attribution. The reviewed QEMU tag object resolves to the existing evidence commit; no release-signature or immutable-build verification is claimed.
2. **Executable checks.** The final complete suite passes **141 tests**: 125 existing tests and 16 new runner tests. All six existing validators pass. The original guest was cross-compiled and executed through explicit TCG. A real AArch64 guest with a deliberately changed marker was rejected with exit 1.
3. **Independent review and clean reproduction.** A separate reviewer inspected the code/docs, exercised real host subprocess fixtures independently of the mocked tests, and approved the corrected implementation. A clean export of the staged implementation, without local generated files, passed all 141 tests, all six validators, guest compilation and the real TCG smoke run. Both hosted jobs subsequently passed against the exact published implementation commit before P005 was checked complete.

The independent review found an oversized finite-timeout bug: `1e100` could overflow Python's process-wait machinery. The final runner rejects it before launch. The exact reproducer, a value immediately above the cap and the accepted upper boundary were rechecked. Review also narrowed the TCG rule to guest-execution tests so device-only QTest remains possible, and corrected the hardware-acceleration source mapping. No review finding remains unresolved.

### Local runtime provenance

Host: Ubuntu 24.04 x86_64; Python 3.12.14. Emulator: QEMU 8.2.2, Ubuntu package `1:8.2.2+ds-0ubuntu1.18`. Compiler: AArch64 GCC 13.3.0, Ubuntu `13.3.0-6ubuntu2~24.04.1`; binutils 2.42. The original Makefile uses `-nostdlib -nostartfiles -static -Wl,--build-id=none -Wl,-T,linker.ld`. The runner uses the command in the ADR with its default eight-second timeout.

The first local emulator invocation failed cleanly because installation without recommended packages omitted `efi-virtio.rom`. Installing the distribution's `ipxe-qemu` dependency resolved the missing ROM; both successful executions above occurred afterward. No substitute accelerator or changed board was used.

| Local build | Guest ELF SHA-256 |

The two ELF hashes differ: inspection with `readelf` and byte comparison isolates the difference to GCC's temporary object filename in the local `FILE` symbol (`ccMa0ogd.o` versus `cceVAr4W.o`). Their loadable guest contents agree. This phase claims successful clean reproduction of behavior, not bit-for-bit reproducible binaries. Deterministic build metadata/artifacts remain later foundation work, including P025/P029; no build recipe is changed here to imply those phases are complete.

## Scope, deviations and remaining work

No deviation from P005's acceptance condition. Only P005 is newly checked; P006–P365 remain unchecked. The small runner changes make the selected execution path explicit and prevent false smoke success; they do not complete P026's future general runner work. The 300-second maximum is a smoke-test budget, not emulated hardware timing.

P006's licensing review, P017's immutable build pin and all later phase-specific checks remain open. The reviewed QEMU 11.1.2 source snapshot and locally executed distribution QEMU 8.2.2 are deliberately distinguished. No Apple CPU, MMIO device, firmware asset, custom T8103 board or Linux image was added. The hardware map and generic assembly/linker payload remain unchanged. P005 grants no new runtime fidelity classification and cannot certify G4, macOS, graphics or cycle timing.
