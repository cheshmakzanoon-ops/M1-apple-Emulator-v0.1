## Research findings that affect implementation

- QEMU's combined emulator, individual files and separate firmware are different licensing units. TCG is not uniformly permissive. Future imports retain their actual notices and source provenance.
- Asahi documentation is CC BY 3.0. Its cited hardware facts and original summaries are distinguished from copying its expressive documentation.
- The reviewed m1n1 README distinguishes MIT code released through 1.9.9 from GPLv2-or-later starting at 2.0.0, with separate embedded-component terms. No m1n1 build dependency is selected.
- Ubuntu's `pkg-config` package provider must be identified; the command name alone does not select freedesktop pkg-config's license.
- Future GPL binary releases use the project's selected accompanying corresponding-source procedure, including the actual patches, configuration, interface definitions and build/install scripts. Firmware and linked libraries receive separate review.

Each finding is supported by the policy's primary-source inventory. Reviewed upstream revisions identify evidence; they do not complete P017's immutable build pin or later build/guest preparation.

## Limits and remaining work

There is no deviation from P006's acceptance scope. The checker is a source-inventory and recorded-policy gate; it cannot prove authorship, detect every encoded proprietary payload, authenticate remote terms, settle every derivative-work question or audit unexamined release artifacts. Its default mode reads current working files, including tracked ignored files, while ignored untracked local outputs remain excluded. Strict archive mode covers every file in the selected export. Both are bounded observations, not a compliance certificate.

Review-input digests detect changes to known declaration/build/runner surfaces; refreshing a digest is a human review decision, not a dependency resolver or permission grant. Exact new files also require provenance review. Future third-party imports require an expanded inventory with original licenses/notices, and future binaries/containers need a complete outgoing-file, dependency and corresponding-source review.

The root MIT license and hardware registry are unchanged. P007–P365 retain their own acceptance checks. No runtime gate, Linux/macOS compatibility, GPU graphics or cycle accuracy is awarded by this phase.
