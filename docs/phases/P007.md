# P007 — Establish a single main branch policy

**Status:** complete for P007's contribution-policy acceptance condition after
local, independent and exact-commit hosted verification.
**Review date:** 2026-10-24. **Branch:** `main`.

**Selected target:** Apple M1 / T8103 / H13G; Mac mini (M1, 2020), board J274.

**Runtime boundary:** this phase defines and checks the contribution workflow.
It does not add Apple CPU/device behavior or award an emulation gate. The real
guest check remains the existing generic QEMU `virt` experiment with explicit TCG.

## Requirement and acceptance evidence

The unchanged canonical requirement is **document one authoritative development
branch, safe review and tested commits**. Its acceptance check is **contribution
instructions do not demand auxiliary branches**. Work starts from
`c0e6acf6246f7acf13bdc566900b3d64b21cd15c`, the completed P006 baseline.

| Requirement | Implementation |
|---|---|
| One authoritative development branch | [CONTRIBUTING.md](../../CONTRIBUTING.md) defines `main`, preserves the owner's explicit-exception rule and requires no auxiliary branch or pull request. Existing refs are never deleted by the guard. |
| Safe review | Explicit selected-path staging, review of the staged diff, independent review when available, source/licensing checks and conflict handling that preserves existing work/history. |
| Tested commits | Record the parent and index tree, compare an exported tree's paths/blob IDs/executable modes, then run all validators, the complete suite and real generic smoke in that export. Check committed parent/tree and publish the immutable checked SHA. |
| Concurrent work and publication | Normal synchronization is fast-forward-only. Non-forced publication targets only `refs/heads/main`; divergence requires integration review and retesting. Verify both hosted jobs for that exact SHA. |
| Executable checks | [Policy validator](../../tools/validate_branch_policy.py) checks the visible contract, entrypoint links, common unsafe instruction patterns and supported CI trigger form. `--checkout` separately checks attached local `main`, Git state and cached remote ancestry without changing the checkout. |
| Regression and project integration | [Focused tests](../../tests/test_branch_policy.py), CI, engineering/development guidance, eleven target declarations and an explicitly reviewed licensing inventory cover the new workflow. |

The default validator is offline and works in detached CI checkouts and source
exports. The strict checkout mode is a local precommit guard, not a demand to
create a branch for hosted verification. The optional existing pull-request
event is restricted to target `main`; it does not make PRs a contribution step.

## Research and design decisions

[Primary Git and GitHub references](../REFERENCES.md#p007-contribution-workflow-evidence)
support the workflow. Git's index and working files can differ, so tests of an
arbitrary working tree are insufficient evidence for the next commit. Archive
attributes can affect exports; full path/blob/mode comparison prevents an
altered or incomplete archive from silently becoming the test subject. A plain
commit and postcommit identity comparison guard against changed staging or hooks.

Publishing a captured commit SHA avoids a race in which local `HEAD` changes
between verification and push. Ordinary fast-forward restrictions preserve
concurrent remote work. GitHub push checks run after publication, so this policy
does not claim that the server prevented all untested pushes or configure a
required-PR protection rule.

P006 remains intact. Four new files are original project work, and the two new
reviewed inputs use the existing external Git/Python/host tools. The inventory
now contains 52 source paths, twelve external/reference dependency groups and
nine reviewed input digests. No third-party source or binary is bundled. The
hardware registry, executor, guest assembly and Linux witness are unchanged.

## Review findings and corrections

- Publish the saved SHA rather than mutable `HEAD`; an independent local-remote
  reproducer showed that the latter can publish a concurrent untested commit.
- Disable optional index refresh and Git's filesystem monitor for the local
  guard; a regression proves a configured monitor hook is not executed.
- Reject active configured clean/process filters before a quiet diff could execute
  them; regression fixtures verify that both forms leave a side-effect marker
  absent. Disable implicit fetching of missing Git objects.
- Recognize attached branch-creation flags, extra push destinations and commit
  flags/path arguments that change the tested index selection.
- Report an invalid/self-referential root as a nonzero diagnostic rather than a
  traceback.
- Independently exercise the export checker against omitted paths through
  export attributes, modified bytes and changed executable bits.

## Limits and remaining work

The policy lint recognizes a fixed visible contract, four contribution entrypoints,
common instruction patterns and the current simple CI event syntax. It is not a
complete Markdown, YAML or shell interpreter and cannot prove every sentence or
script safe. Human review remains part of the acceptance procedure.

The checkout guard observes local state and cached `origin/main`; it does not
authenticate a remote, prove freshness, configure protection, run the suite or
certify review/CI results. Failed checks preserve the checkout for review instead
of attempting automatic repair. Existing access controls remain in force.

This is P007 only. P008–P365 retain their independent requirements; G4 remains
unrun. No Apple CPU, T8103 Linux/macOS, GPU or cycle-accuracy capability is added.
